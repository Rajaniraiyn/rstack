# Code slop

Remove AI-generated cruft from code without changing behavior. Match the surrounding file and codebase.

## Comments

- Comments that restate the code: "increments the counter by 1" above `i++`. Remove.
- Comments that explain why, with a non-obvious reason. Keep.
- Commented-out code. Remove. Version control has the history.
- Section banners and "// ==== init ====" dividers. Remove unless the file already uses them consistently.
- Attribution comments: "generated by", "added by AI". Remove unless the project requires them.

## Defensive checks

- try/catch around calls that cannot throw. Remove.
- Null and undefined checks on values the type system already guarantees. Remove.
- Optional chaining stacked three deep on trusted data. Simplify.
- Redundant defaults when the library already provides them. Remove.
- Keep checks on real failure modes: network, parsing, untrusted input.

## Casts and type abuse

- Casts to `any` used only to silence the type checker. Replace with a real type.
- Non-null assertions that only satisfy a linter. Fix the type instead.
- `any` as a result type where the concrete type is known. Type it.
- Unused generic parameters and type parameters. Remove.

## Structure

- Deep nesting that early returns would simplify. Convert.
- A helper with a single call site. Inline it, or keep it only if the name carries real meaning.
- `async` for synchronous work. Drop the `async`.
- Reimplemented library or standard library functions. Use the library.
- Micro-optimizations with no measured win. Remove.
- Abstractions, config, and extensibility for cases nothing uses. Remove until a real need appears.

## Dead weight

- Unused variables, parameters, imports, and exports. Remove.
- Unreachable code and empty branches. Remove.
- Debug logging and console noise. Remove.
- Duplicated blocks with no stable center. Remove the duplicate, or factor out only when the duplication is stable.

## Style consistency

- Match the file's existing naming, return style, error handling, and blank-line rhythm.
- Prefer the file's conventions over your own habits.
- Two blank lines here, one there. Match the file.

## Magic numbers

- Name them when they are meaningful and the name adds meaning.
- Don't introduce constants for the sake of it. A threshold used once with a clear context can stay.
